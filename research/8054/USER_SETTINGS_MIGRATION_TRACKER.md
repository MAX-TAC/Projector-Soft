# PRODUCT-MIGRATION — полный перенос пользовательских настроек KuSettings в TvSettingsPlus MOD v41

Дата: 2026-11-20. Источник истины: [96-функциональная матрица](FINAL_FUNCTION_PARITY_8054.csv). База реализации: PR #2 `fbb41e92`. Разработка: изолированная ветка `feature/8054-user-settings-migration-20261120`. **Без ADB, без изменения проектора.**

## Цель

Оставить дизайн, меню, страницы и D-pad v41; перенести **все пользовательские настройки** оригинального KuSettings в собственные обработчики MOD. В рабочем пользовательском маршруте **не запускать** `com.my.settings` Activity/Fragment/Controller. Платформенные Wi-Fi, Bluetooth, приложения и системные сведения Android TV оставлять штатными. Службы TvServices, KuSourceRJ, autofocus, keystone и HAL сохранять.

**Важно:** `WORKING_STATIC` / `DIRECT_MOD` в исходной матрице не означают подтверждённую аппаратную работу. Ни одна функция не становится `HARDWARE_VERIFIED` без реального теста.

## Принцип выполнения

1. Для каждого OEM-пункта определить оригинальный callback и его **непосредственный** Android/OEM backend (Global/System/property/Service/API).
2. Подключить этот backend к уже существующей строке v41; только если строки нет — добавить строку в соответствующий раздел. Никаких ссылок в китайское UI.
3. Использовать исходные OEM диапазоны/списки и допуски; не менять заводские калибровки. Проверять результат через настоящий getter там, где он имеется. Ошибки не должны менять другие пункты.
4. Завершать перенос **группами функций**, не останавливая остальную разработку из-за одного невыясненного пункта. Отдельный аппаратный тест, исходное значение и восстановление — прежде чем отмечать подтверждённую работу.
5. После UI-марафона мигрировать только подтверждённые необходимые фоновые зависимости KuSettings (BootupReceiver/MySetTimeService), отдельно проверить холодную загрузку, пульт, вентилятор и восстановление; только затем разрешать испытание отключения пакета с планом возврата.

## Обновление 21.11.2026: штатные Picture controls Android TV уже физически работают

Владелец подтвердил на работающем FlixTone 8054, что **оригинальные `com.android.tv.settings` → «Экран и звук» → «Изображение»** уже изменяют яркость, контраст, насыщенность, оттенок, резкость и RGB нижними D-pad ползунками. Значения синхронизируются с китайским меню. `picture_contrast` наблюдался как `57 → 93 → 50 → 64` после **нескольких** ручных корректировок, не как точный OEM шаг. Цветовая температура User/Cool/Standard/Warm и MJC/MEMC эффекты (Off/Low/Medium/High) присутствуют; demo не является обязательной функцией. Подробности: [OWNER_STOCK_ANDROID_PICTURE_OBSERVATION_20261121.md](OWNER_STOCK_ANDROID_PICTURE_OBSERVATION_20261121.md).

**Новое приоритетное решение:** НЕ дублировать уже работавшие штатные Android TV Picture обработчики через второй самостоятельный D-pad writer; в первую очередь **использовать оригинальный `com.android.tv.settings.partnercustomizer.picture.PictureActivity/PictureFragment`** внутри навигации v41. Это **не `com.my.settings` Chinese GUI**. Допустим минимальный адаптер маршрута с сохранением восьмираздельного MainSettings. Если оригинальный Fragment не интегрируется без дефекта — переносить только необходимый callback, а не весь MediaTek HAL.

Текущий кандидат PIC03–10 с собственным `Settings.Global.putInt` в PR #5 **остаётся экспериментальным и не должен выпускаться как штатная замена**, пока не принято решение о stock reuse. Отключение всего KuSettings по-прежнему заблокировано boot/TIME_TICK/TimeService зависимостью. Не считать cross-UI синхронизацию доказательством разрешения удалить пакет.

## Что изменено в текущем PR

**PIC03–PIC10:** существующий нижний `NativePicturePanel` теперь содержит прямой кандидат для LEFT/RIGHT → `Settings.Global.putInt` → штатный TvServices → повторное чтение Global + `TVSettingConfig.getConfigValueInt`. Сохраняет исходное значение (только журнал, без авто-отката), отказывается от следующего шага до backend readback, защищает от изменения mode/temp/HDR и исправляет закрытие диалога при ожидаемом ContentObserver эхо. **Шаг +1/−1 предварительный; реальный OEM increment неизвестен.** Активный HDMI и hardware effect не доказаны. Кандидат не предназначен для бесконтрольной установки до теста и не меняет статус остальных пунктов.

**PIC01/PIC02/PIC11/PIC12** требуют отдельного анализа переключения режимов. **PIC14**, формы геометрии, функции питания и EDID не включены этим кандидатом. PR #4 с чистой политикой контраста остаётся отдельным исследовательским экспериментом, его не нужно притягивать runtime-зависимостью.

## Обнаруженные маршруты, которые нужно удалить к завершению переноса

- `OemProjectionPanel.projectionIntent()` в унаследованном маршруте 8054 может намеренно запускать **`com.my.settings.activity.ProjectionActivity`** по `android.settings.PROJECTABOUT_SETTINGS`. Этого в финальной версии не должно оставаться. Текущий v41 раздел `NativeSections.Projection` уже имеет собственные пункты, но ссылки на оригинальные редакторы/незавершённые функции ещё есть. **Не удалять единственный рабочий путь к коррекции до переноса его операций.**
- `OemHardwareDelegatedSettings` и `OemAdvancedSoundRoutes` используют `com.android.tv.settings` (OEM-экраны внутри Android TV Settings), **не** тот же пакет, что KuSettings. Они не блокируют удаление `com.my.settings` как зависимость пакета, но финальные пользовательские настройки следует по возможности встроить непосредственно в v41.
- Для финального пункта `KUS_INDEPENDENT` отдельно проверить не только явные Intent, но и неявные Actions, `PackageManager.resolveActivity`, BroadcastReceiver, ContentProvider и Service зависимости на exact-8054. Удаление только ярлыка KuSettings не является выполнением задачи.

## Контрольные точки готовности

- **UI_DELIVERED:** функция реализована собственным MOD обработчиком, нет старого `com.my.settings` UI.
- **ANDROID_COMPILED:** exact-8054 Java/AndroidX и APK собираются в CI, D-pad и Back не ломаются.
- **DEVICE_CONFIRMED:** проверены чтение, одно изменение, реальный эффект и восстановление на данном 8054.
- **KUS_INDEPENDENT:** нормальная эксплуатация, boot и восстановление критичных OEM-служб без `com.my.settings` подтверждены отдельно.
- **KUS_REMOVABLE:** только после KUS_INDEPENDENT + гарантированный откат. Не удалять `KuSourceRJ.TimeService`, TvServices или драйверы.

## Необходимое участие владельца

Сейчас от владельца не требуется выполнять команду или менять проектор. Перед первым аппаратным тестом отдельно предоставим **конкретные ADB-команды read-only** и один последовательный STOCK-тест с первоначальным значением, одним шагом и восстановлением. Следующая кандидатура MOD также требует отдельной инструкции по безопасной установке и откату; предыдущий контрольный APK сохраняется.

## Известные ограничения текущего изменения

- `Settings.Global.putInt` должен исполняться в правильном привилегированном контексте OEM APK; подтвердить только на exact-8054.
- Активный input/source и SDR/HDR scope не удостоверены независимым getter, исходное значение в журнале поэтому **не** является безопасным автоматическим restore.
- Дельта штатного D-pad пока не измерена; все восемь простых слайдеров считаются software candidates, а не завершёнными настройками.
- Статус модели в `FINAL_FUNCTION_PARITY_8054.csv` до аппаратной проверки не повышать.
