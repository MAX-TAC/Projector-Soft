# EDID 8054: Settings.Global → TvServices, статическая цепочка

Источник: оригинальные 8054 APK из backup ZIP SHA-256 `4f53f2224c98b4c832a19a591b9dd7f925bde28528b5674a09732c0f0e41d362`; [TvSettingsPlus trace, run 44106214713](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44106214713), [TvServices/MtkTvInput scan, run 44107731141](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44107731141), [itemIds consumers, run 44109768484](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44109768484), [async update trace, run 44111398773](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44111398773). TvSettingsPlus.apk SHA-256 `f8e0c6fe0f46e7eb8db651c31d85ef8b32a769b37e4dd0f96ed19a64725d74ee`; TvServices.apk SHA-256 `2934ca9334afd0a2af85786aa0593d27da216086c7eb9b0c9b801f412516b77d`; MtkTvInput.apk SHA-256 `59040206f84c7fbd85f61f885cb5edbdd977ebea3a2a3b20a6b7afc138df72b2`.

1. В `TvSettingsPlus` два OEM getter: `EdidSourceSecondaryController#getEdidVersion` и `SourceSubMenuController#getEdidVersion` передают `0x6` в `MtkTvAVModeBase#getVideoInfoData` и читают `getU8EdidIndex`. Восемь radio `onClick` в secondary controller и fragment пишут значения 0..3 в один `Settings.Global.tv_input_hdmi_edid_version` через `SettingsUtil#putGlobalValueInt`. В этих обработчиках физический порт не передаётся.
2. `TvServices.TVMenuSettingsService#initMapdata()V`, `smali/com/mediatek/tv/agent/TVMenuSettingsService.smali:3051-3058`, кладёт в `itemIds` карту `"tv_input_hdmi_edid_version" → "g_fusion_picture__hdmi_edid_version"` с вызовом `Map#put`. В конструкторе этой службы строка присутствует в перечне настроек на строке 529. Это точное соответствие имён, а не ещё доказанный вызов `MtkTvConfig#setConfigValue` или иной HAL.
3. Read-only поиск точного литерала по распакованным smali дал: TvSettingsPlus 20 вхождений, Factory 1 (поле константы), KuSettings 0, MtkTvInput 0, TvServices 2. Отсутствие литерала в MtkTvInput не исключает вызова через Binder/конфигурационный ID или native слой.
4. `TVMenuSettingsService#syncConfigDataToSetting()V`, строки 4933-4971, передаёт весь `itemIds` в `updateSettingDB(Map)`. `updateConfigDataChanged(String)`, строки 5378-5627, делает то же для отдельных категорий изменений. `formatSettingToConfigId(String)`, строки 1179-1192, возвращает `itemIds.get(key)`; его callsite пока нужно найти.
5. `updateSettingDB(Map)`, строки 5755-5805, передаёт карту в `TVAsyncExecutor#execute` как `TVMenuSettingsService$2`. `$2#run()V`, строки 42-265, перебирает `Map.Entry`, читает `TVSettingConfig#getConfigValueInt(entry.value)` (строка 83), сравнивает с `getSettingStringValue(resolver, entry.key)` и при отличии вызывает `putSettingValueInt(resolver, entry.key, value)` (строки 165/196). Это направление **config → Settings**. `getSettingStringValue`, строка 6164, вызывает `Settings.Global#getString`; `putSettingValueInt`, строка 6707, вызывает `Settings.Global#putInt`. `access$600` также вызывается после записи; его назначение не установлено. Перегрузка `updateSettingDB(Map,int)` использует аналогичный `$3#run()V`.
6. Обратный путь: `TVMenuSettingsService#<clinit>`, строки 201-210, берёт `BASE_URI` из `Settings.Global.CONTENT_URI`. Конструктор кладёт EDID key в регистр `v124` (строка 529), `filled-new-array/range {v3 .. v161}` создаёт `prefKeys` (строки 606-610), а `access$100` возвращает `prefKeys` (строки 648-655). `$1#run`, строки 38-86, регистрирует `SettingObserver` для каждого элемента этого массива на URI из `buildUri(key)` (строки 1009-1028). `SettingObserver#onChange`, строки 52-205, снимает имя key из URI, вызывает `formatSettingToConfigId(key)` и для обычной ветки `updateConfigData(configId,key)`. `updateConfigData`, строки 4986-5376, читает значение Global через `getSettingStringValue`, сравнивает с конфигурацией и в общей ветке вызывает `TVSettingConfig#setConifg(configId,int)` на строке 5299. `TVSettingConfig#setConifg`, строки 472-508 в **TvServices.apk**, вызывает `MtkTvConfigBase#setConfigValue(configId,int)` на строке 503. Специальные ветки для видео/звука и условия раннего выхода видны в smali; для EDID динамическая достижимость общей ветки ещё не проверена. [Observer/callsite run 44112728599](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44112728599), [URI/getter/setter run 44115028456](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44115028456), [MTK setter run 44115598445](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44115598445), [array run 44119451026](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44119451026), [accessor run 44120157009](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44120157009).

**Открытая зависимость:** `MtkTvConfigBase#setConfigValue` не прослежен до native/HAL и не исполнен в аппаратном тесте. Не установлены семантика `g_fusion_picture__hdmi_edid_version`, привязка к HW6/HW7 и необходимость hotplug. Поэтому MOD C1 продолжает скрывать legacy single-port selector на 8054. Штатная OEM-страница остаётся доступной.

**Тест после разрешения владельца:** сначала только чтение ключа, HDMI source IDs и EDID readback отдельно на HW6/HW7 с сохранением исходного состояния. Любая запись EDID или переподключение HDMI требует отдельного разрешения и проверенного пути восстановления исходного значения. В текущем аудите записи и аппаратных тестов не было.
