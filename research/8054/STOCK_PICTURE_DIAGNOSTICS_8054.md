# STOCK 8054 · диагностика PIC03–PIC05

Текущий статус `PICTURE_NATIVE_UI_READ_ONLY / BUILT_UNTESTED`. Два отдельных разрешения владельца: A на read-only подключение, B на ручную регулировку контраста в штатном UI. Ни одну фазу не выполнять заранее. Работать с исходниками этой ревизии. Архив проверенного комплекта 44312569432 и контрольный APK 9f8fc64 используются как зафиксированные артефакты.

## A. Один снимок с компьютера владельца

Нужны Python 3.10+ и обычный ADB. Из корня репозитория выполнить после разрешения, подставив согласованный серийный номер. Каждому снимку нужен новый каталог. Без `--out` инструмент создаст временный каталог на компьютере. Linux использует `/tmp`.

```sh
python3 install-kit/preflight.py --picture-stock --serial "APPROVED_SERIAL" --out /tmp/stock8054-hdmi1-before
```

```powershell
python install-kit/preflight.py --picture-stock --serial "APPROVED_SERIAL" --out "$env:TEMP\stock8054-hdmi1-before"
```

Команды ниже приведены без общего префикса `adb -s APPROVED_SERIAL`. При `STOP` отчёт содержит последний проверенный барьер. Нужны статус `device`, UID 2000, машина 8054, API 33, единственный системный путь и SHA-256 точного STOCK. Отказ в чтении SHA считается `STOP`. Этой ветке не нужны APK для установки, `aapt` или `apksigner`.

| Команда | Полезный результат и ограничения |
|---|---|
| `get-state`, `shell id` | Выбранный транспорт доступен, обычный UID shell |
| `shell getprop ro.rjpj.machine.id`, `shell getprop ro.build.version.sdk`, `shell getprop ro.build.fingerprint` | Модель, API, строка сборки для сопоставления с резервной копией |
| `shell pm path com.android.tv.settings` | Точный путь `package:/system_ext/priv-app/TvSettingsPlus/TvSettingsPlus.apk`; /data update или дополнительные APK останавливают сбор |
| `shell sha256sum /system_ext/priv-app/TvSettingsPlus/TvSettingsPlus.apk` | Хеш `f8e0c6fe0f46e7eb8db651c31d85ef8b32a769b37e4dd0f96ed19a64725d74ee` |
| `shell settings get global picture_mode` | Режим провайдера до и после сбора значений. Различие означает неполный снимок |
| `shell settings get global picture_brightness`, `shell settings get global picture_contrast`, `shell settings get global picture_saturation` | Три независимых сохранённых значения. `null`, отказ и неожиданный формат остаются неизвестными |
| `shell dumpsys tv_input` | Зарегистрированные inputs, их состояния, активные сессии, если OEM выводит их однозначно. Cable connected и HW6/HW7 сами по себе не подтверждают источник основного видеотракта |
| `shell dumpsys display` | Состояние дисплея и возможные сведения о HDR. Список HDR capabilities не определяет текущий SDR/HDR сигнал |
| `shell dumpsys package com.mediatek.tv.service`, `shell dumpsys activity services com.mediatek.tv.service` | Сведения PackageManager и ServiceRecord, если доступен. Отсутствие строки `TVMenuSettingsService` сохраняется как `UNVERIFIED` |
| MediaTek config и min/max | Подтверждённого интерфейса для обычного ADB shell нет. `TVSettingConfig` и `TVNative` — внутренние API. Простого вызова из ADB для них не найдено; инструмент их не вызывает |

`stock-picture.json` и отдельные `.txt` остаются локально. `CAPTURED` (код 0) означает, что четыре значения Global прочитаны и режим совпал на концах. `PARTIAL` (2) означает неполные provider данные, `STOP` (1) означает провал проверки STOCK или локального вывода. Дампы имеют собственные статусы `OBSERVED / DENIED / UNAVAILABLE`. Даже `CAPTURED` сохраняет active source, main input и signal format как `UNVERIFIED`, пока их не сверит оператор. Снимок не обеспечивает атомарность. Рядом с результатом оператор записывает время, видимый источник Android TV/HDMI1/HDMI2, показанный штатным UI формат SDR/HDR и состояние стабильного сигнала. Если формат или вход не подтверждены штатной индикацией, отметить «не установлено».

## B. Один шаг контраста через STOCK UI

Выполняется вручную после второго разрешения. Все повторные снимки используют фазу A, каждый в новом каталоге.

1. На исходном входе сверить источник, режим и формат сигнала. Записать видимый уровень контраста, значение PIC04 в Global и, при наличии уже доступного штатного read-only интерфейса, значение ACFG. Если исходный уровень недостоверен, вход меняется или возвращение в исходный режим не гарантировано, тест не начинать.
2. Сдвинуть штатный ползунок контраста ровно на один шаг. Дождаться стабильного сигнала и совпадения двух последовательных показаний с указанным временем. Снять Global, доступный ACFG и отдельно описать видимое изменение на том же изображении.
3. При доступном втором HDMI или втором режиме переключить только один фактор. Снять значения и затем вернуться на исходный вход, режим и формат. Снять их повторно до восстановления. Если переход неоднозначен, прекращать новые регулировки и сначала восстановить исходный контекст.
4. Вернуть исходный контраст штатным UI. Проверить видимый уровень, Global, доступный ACFG и изображение. Если значения разошлись, остановить тест и сохранить все снимки. Автоматический replay исключён.

В отчёте четыре отдельных поля: Global, ACFG (или «недоступен»), наблюдаемое изменение изображения и сохранение между профилями (подтверждено/неподтверждено). Совпадение Global с заказанным значением подтверждает только провайдер. Один стабильный случай не покрывает смену режима/HDMI во время обработки.
