# Звук 8054: ручная проверка и восстановление

Статус кода a53daf0: BUILT_UNTESTED, не hardware verified. План не выполнялся. Любые действия на проекторе, включая чтение через ADB, установку APK, смену входа/режима и подключение устройств — только после отдельного разрешения владельца. PR остаётся draft.

1. **Сохранить вне приложения:** версию APK/прошивки, текущий вход и выход, громкость, CEC/eARC, sound_style, bass/treble/surround и пять EQ. Для чтения использовать `adb shell settings get global <key>`: `sound_style`, `sound_bass`, `sound_treble`, `sound_sound_surround`, `sound_equalizer_detail_120hz`, `sound_equalizer_detail_500hz`, `sound_equalizer_detail_1500hz`, `sound_equalizer_detail_5000hz`, `sound_equalizer_detail_10000hz`. Отсутствующие значения записать как отсутствующие, не заменять нулём. Сфотографировать исходные значения в OEM UI. Baseline OemSoundPanel живёт только в объекте страницы и не заменяет этот внешний протокол.
2. **Проверить навигацию:** D-pad фокус на режиме, slider, EQ, Refresh; после `removeAll()` и пересоздания категории фокус виден, кнопки доступны. Открыть «Звук · штатные настройки»: explicit `com.android.tv.settings.uicustom.MainActivity` с `android.settings.SOUND_SETTINGS` должен показать звук, не корневую страницу/петлю.
3. **Проверить смену режима:** выбрать один штатный sound_style, нажать Refresh. Сравнить весь набор UI с Global и оригинальным UI. До Refresh старые callbacks обязаны отклонять запись другого режима. Если OEM ещё синхронизирует значения — повторить чтение/Refresh; два одинаковых чтения режима не гарантируют атомарный DSP snapshot.
4. **Проверить один параметр за раз:** bass, treble, surround, одна полоса EQ. Сверить Global readback и услышанный эффект на том же контрольном фрагменте при неизменной безопасной громкости. Запись Global не доказывает эффект DSP. Изменение режима может сбросить несколько значений — записать все отличия.
5. **Ручной rollback:** в оригинальном OEM UI вернуть исходный режим; дождаться завершения его синхронизации, перечитать всю группу. Затем вернуть доступные исходные значения в том же входе/выходе. Снова сверить оригинальный UI, Global и звук. Если значение отсутствовало/недоступно или профиль изменился, не создавать ключи и не делать массовый `settings put`: остановить тест, сохранить расхождение и использовать штатный путь восстановления. Автоматического replay, удаления ключей или factory reset этот план не разрешает.
6. **Проверить границы страницы:** повторный Refresh не меняет первый baseline; новое открытие/перезапуск создаёт новый baseline. При частичном исключении populateSound должны оставаться OEM-переход и Refresh. Это отдельная runtime проверка с диагностической сборкой/логом ошибки; не вызывать аппаратную ошибку ради теста. JVM SoundPanelState тест её не доказывает.

| Выход | Ограничение и отдельная отметка результата |
|---|---|
| Динамики | Базовый проход выше; записать влияние каждого контрола |
| Bluetooth | Не считать DSP/EQ одинаковым с динамиками; отдельно проверить профиль и возврат исходного маршрута, пульт/AutoPair не отключать |
| HDMI ARC | Записать физический порт и состояние CEC/receiver. Влияние EQ на ARC не предполагается |
| HDMI eARC | Отдельно подтвердить поддержку, порт, CEC и handshake. Использовать OEM UI; прямой raw toggle MOD отсутствует |

Для каждого выхода: PASS/FAIL/NOT_TESTED, исходные и итоговые значения, слышимый эффект, результат ручного возврата. Не переносить вывод одного выхода на другие. Переключение CEC может затронуть eARC и питание подключённых устройств — выполнять только в согласованном тесте. До выполнения этих проверок состояние аппаратуры — RUNTIME_TEST_REQUIRED.
