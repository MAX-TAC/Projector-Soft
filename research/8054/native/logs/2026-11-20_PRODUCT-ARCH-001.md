# 2026-11-20 / PRODUCT-ARCH-001 — Chinese UI retirement clarification

## User request / reason
Owner correctly challenged ambiguous diagram `STOCK button → OEM handler → MOD handler → test`: project objective is to eliminate the Chinese settings GUI, not route MOD through it. The prior diagram was *research chronology*, not a correct runtime topology; it could mislead an implementing agent.

## Confirmed design rule
- Chinese UI is reference **only** during offline reverse engineering and authorized A/B stock testing.
- All *migrated* settings must execute from `TvSettingsPlus MOD UI → MOD-owned handler → independent backend → hardware`.
- The runtime chain must not call `com.my.settings` Activity/Fragment, depend on Chinese UI controller lifecycle, or use hidden proxy UI launches.
- Preserve distinct hardware services e.g. TvServices, KuSourceRJ/TimeService, RuiAutoFocus, TRD; don't assume removing GUI means removing vendor backend.
- `com.my.settings` full package disabling is a **separate unmet milestone**; must first prove one safe replacement for critical KuSourceRJ TimeService recovery and check cold boot, fan/thermal and Bluetooth/remote.
- MOD v41 is **not yet proven** UI/package independent for all 96 functions. Need static + hardware acceptance evidence; a contract alone is not implementation.
