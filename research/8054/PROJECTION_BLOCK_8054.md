## Точные точки входа PRJ06/07/10

Оригинальный `ProjectorSubMenuController` через `$5/$6/$7.onClick` вызывает `FloatMenuManager.jumpByAction(String)`. Он создаёт внутренний `Intent(action)` без extras (1883–1894). Внешняя обёртка передаёт этот Intent и параметры возврата в боковую панель: `menu_index`, `focus_id` и при необходимости состояние вторичного контроллера. Эти данные принадлежат навигации самой боковой панели.

Независимые штатные вызовы подтверждают прямой запуск. `KuSettings.IntentUtils.imageDigitalIntent` передаёт действие DIGITAL_ZOOM в двухаргументный `intentAction` (391–488). `KuSourceRJ.IntentUtils.fourPointIntent` и `keystoneIntent` используют тот же контракт для FOUR_CORNER и HV (317, 424). Оба варианта создают action Intent, добавляют `FLAG_ACTIVITY_NEW_TASK`, разрешают его с `MATCH_DEFAULT_ONLY` и вызывают `startActivity`. Этот маршрут обходится без extras и без подготовки через broadcast. Для каждого action точный Manifest KeystoneCorrection объявляет отдельный exported Activity и DEFAULT. [Трасса запуска и Manifest](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44397417775/job/135130932230)

`OemProjectionPanel` добавляет три отдельных пункта для 8054. До показа и при нажатии проверяет соответствие action → компоненту `com.rjpj.tcorrection`, системный пакет, enabled Activity и application, доступность для UID/exported и permission. При отказе остаётся общий штатный маршрут. `KeystoneCalibrationActivity` сохранён отдельным пунктом.

При открытии исследованные `onCreate` устанавливают layout, инициализируют виджеты и заголовок. `onResume → initData → checkDisplay` перечитывает восемь `persist.rjpj.fourcorner.keystone_*` и рисует редактор. Открытие не вызывает найденных setter/reset; Intent не несёт ID HDMI. Эти сведения не устанавливают аппаратную область хранения по источникам. FourCorner направляет D-pad в `setHorizontal/setVertical → KeystoneUtil.set*Offset`. DigitalZoom направляет D-pad в `setZoom → KeystoneUtil.adjustPixel` и использует те же сохранённые координаты. Отдельные команды редактирования и сброса принадлежат штатным экранам. Проверка Back/D-pad и возможных переходов на реальном дисплее остаётся обязательной. ## PRJ08 / PRJ09: подтверждённые ограничения exact-8054

- `KeystoneSettingsSecondaryController.onAttach → initData → initView → initListener` считывает `persist.rjpj.autokeystone.{poweron,move}`, `persist.rjpj.screen.alignment`, `persist.rjpj.obstacle.avoidance` и `persist.rjpj.keystone.auto.vertical` через `SystemProperties.getInt(key, 0)`. `initView` при движении = 1 разрешает фокус для зависимых переключателей. При движении ≠ 1 он запрещает фокус и **пишет нули в три зависимых свойства**. `KeystoneSettingsFragment.initView` повторяет этот сброс. Поэтому вход в OEM-коррекцию нельзя считать диагностикой без записи.
- PRJ08. `initListener` прикрепляет `$5.onSwitchChangeListener → access$400 → setAutoObstacleAvoidance`. Setter сохраняет локальное состояние и `persist.rjpj.obstacle.avoidance=0/1` через `SystemPropertiesUtil.set`. Отдельного аппаратного readback и асинхронной операции в setter нет.
- PRJ09. При `Build.A_RJ_CUSTOMER_ID != 0` в float menu виден переключатель (`$3 → access$200 → setAutoScreen`), сохраняющий `persist.rjpj.screen.alignment=0/1`. При `customer ID == 0` вместо него виден пункт, `$4.onClick` передаёт `com.coolux.source/com.coolux.source.activity.AutomaticAdmissionActivity` штатному launcher. Действия запуска отделены от проверки наличия датчика.
- `setMoveAutoKeystone` записывает свойство движения и меняет фокус/состояние трёх OEM-виджетов. Штатный `TitleSwitchView.setSwitchEnable(false)` вызывает `onSwitchChangeListener` при смене состояния, если установлен слушатель. В полном OEM UI это может менять зависимые настройки при выключении движения. Отсоединённые виджеты MOD не имеют этих слушателей, поэтому выключение разрешено только при явном `0` для screen alignment, obstacle avoidance и vertical. Активное или неизвестное значение направляет пользователя к штатному экрану. Сброс отдельно подтверждён при `initView`. [Трасса OEM-виджета](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44471250117/job/135380991321) Переключатели автофокуса используют отдельные OEM callbacks и `persist.rjpj.autofocus.{poweron,move}`. Состояние этих свойств не устанавливает фактическую зависимость сенсоров.
- Выбор ToF/камеры, аппаратная ревизия, реакция потребителя на свойства, совместимость с ручной геометрией/зумом и надёжный возврат исходной геометрии требуют подтверждения. PRJ08/09 остаются `DELEGATED_OEM` с общим входом. Присутствие виджета, свойства или пакета не устанавливает поддержку конкретного проектора. [Трасса exact-8054](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44470457643/job/135378358293)

## Синхронизация PRJ02 / PRJ03 / PRJ05

`OemProjectionSwitches` перечитывает три существующих значения при подключении view и возвращении фокуса окна. При нажатии `ProjectionToggleState` повторно вызывает getter и отклоняет устаревший запрос без записи. После одного OEM-вызова он читает фактически сохранённое состояние и обновляет соседние строки. При недоступном readback строка временно недоступна до успешного чтения. Повторная запись и автоматический откат отсутствуют. Внешнее изменение в том же окне обнаруживается при взаимодействии или возвращении фокуса. Физическая реакция, D-pad, остаточные эффекты OEM и ручной возврат требуют device-теста.

## Короткий device/rollback checklist (пока не выполнялся)

1. Получить отдельное разрешение и сначала подготовить установочный/recovery пакет из следующего milestone. Сохранить вне приложения исходные projection values, фото геометрии/фокуса/ориентации/zoom/brightness/customer ID, активные OEM службы/температуры. Не считать Settings.Global полным calibration backup.
2. D-pad открыть G, Zoom, Brightness по одному; проверить доступность/отказ permissions и Back в MOD. Не открывать OEM-экран трапеции в read-only проверке при выключенной или неизвестной автотрапеции при движении: его инициализация пишет три свойства. Остальные редакторы открывать только после проверки их стартового контракта.
3. Для согласованной функции проверить original range и изменить один пользовательский шаг; вернуть original через тот же OEM UI и перепроверить геометрию/фокус/температуры. Не обращаться к factory reset/calibration, I²C/PWM или motor API. Не останавливать службы для теста отказа.
4. При отсутствии исходного state/понятного ручного возврата — stop test до изменения функции. UI/Intent eligibility не доказывает физический rollback. Результаты по каждому PRJxx остаются NOT_TESTED до реального теста.

Перед первым device test отдельный обязательный пакет: exact MOD + matching sha256 + original8054 APK + preflight PackageManager/signature/sharedUID/SELinux + recovery/D-pad path при нестарте меню. Ни установки, ни включения/отключения системных пакетов, ни записи Global этот документ не разрешает.
