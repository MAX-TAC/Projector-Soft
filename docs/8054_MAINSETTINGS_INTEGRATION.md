# Интеграция оригинального MainSettings на 8054

Ревизия кода v39 — `f894da1`. Владелец проверил v36 и обнаружил, что обычный MainSettings продолжает открывать старое дерево. Точка входа v39 — существующий `com.android.tv.settings.MainSettings` с исходным Manifest. Внутри `createSettingsFragment` та же цепочка `TvSettingsActivity` → `FlavorUtils` → `SettingsFragmentProvider` → `MainFragment`. Сохраняются проверка старта, темы, контейнер и штатный выбор Preview. [Трасса 8054](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44719952065)

## Активный XML и штатные контроллеры

`MainFragment.getPreferenceScreenResId` выбирает `main_prefs_x` (0x7f140051) для flavor 4, `main_prefs_vendor` (0x7f140050) для 8, `main_prefs` (0x7f14004f) для остальных. Библиотечный resolver читает `config_tvSettingsFlavor` через `ResourcesUtil`. Все три точных XML имеют группу `general_settings`, NetworkFragment и AppsFragment. У варианта Vendor и X есть дополнительные группы Basic Mode и варианты каналов со slice. Активное значение overlay на проекторе в этой сессии не считывалось. Адаптер работает с реально созданным деревом после runtime-фильтров и использует заголовок исходной группы. [Карта ресурсов](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44719952065) · [Resolver flavor](https://github.com/MAX-TAC/Projector-Soft/actions/runs/44721991789)

`SuggestionQuickSettingPrefsContainer.showQuickSettings` программно строит `quick_settings` и добавляет `take_bug_report`, когда исходный контроллер считает действие доступным. Поздние рекомендации создаются отдельно в `onSuggestionReady`. Обе категории скрываются как UI. Объекты остаются разрешимы для штатных контроллеров.

В v34 дефект раннего хука был связан с использованием `p0` после `move-result-object p0`. Этот регистр к тому моменту уже содержит View. Причина аппаратного выхода v34 без Logcat полностью не установлена. В v39 вызов `StockMainSettingsMenu.install(PreferenceFragmentCompat)` находится непосредственно **перед** оригинальным `invoke-super` в `MainFragment.onCreateView`. Стоковый вызов, чтение результата, возврат, регистры и остальной метод сохранены. Патч проверяет сигнатуру, инструкции места вставки, единственный возврат, отсутствие обработчиков исключений и запись в p0. По одному переходу в двух методах `SuggestionQuickSettingPrefsContainer` скрывают поздние вспомогательные категории после установки основного дерева.

## Проверки и граница доказательства

Пересобирается `classes13.dex`. Отчёт содержит SHA-256 исходных и новых smali, а также минимальный diff. Повторная декомпиляция кандидата строго сверяется с ожидаемым деревом: единственное исключение — три точно перечисленных булевых поля с одинаковым явным и неявным false. Остальные 15 оригинальных DEX и ресурсы побайтно совпадают. Manifest-узел MainSettings сохраняется, новые Activity используют его тему. В модуле только собственные классы и генерируемые binding-классы, а тестовые AndroidX/OEM-файлы исключены.

AndroidX/JVM загружает производственный адаптер в фикстуре с исходным именем Activity и исходной цепочкой provider. Тест сравнивает реальные видимые элементы адаптера, наличие связей Preview и скрытие поздних рекомендаций. Это проверяет исполняемый адаптер и штатные компоненты OEM-совместимого интерфейса. Сам OEM DEX проверяется статически. Запуск подписанного APK с реальными MediaTek компонентами, ART и пультом требует проверки владельцем. Переход Settings из открытого подраздела указывает на настоящий MainSettings. Глобальный диспетчер клавиш и Source на HOME/HDMI требуют проверки отдельно.
