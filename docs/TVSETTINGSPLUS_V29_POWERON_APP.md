# TvSettingsPlus MOD v29 — нативный выбор приложения при включении

**Статус: экспериментальный APK на базе 8052; программная проверка CI. Не адаптация 8054.**

## Реально перенесённая функция

- `Источники · Проектор → Приложение при включении` стал **ListPreference** вместо перехода к OEM активности.
- Исходный `PowerOnAppSecondaryController` пишет `persist.trd.source_id`: `HOME` означает отсутствие запуска приложения, иначе сохраняется выбранный package name.
- MOD получает список установленных приложений с `LEANBACK_LAUNCHER` или обычным `LAUNCHER`; включаются только пакеты, для которых PackageManager действительно возвращает запускаемый Intent.
- Не разрешено вручную вписывать имена приложений и запускать `com.my.settings`/сам TvSettingsPlus/KuSourceRJ в качестве приложения при включении.
- Перед записью сверяется текущее состояние свойства, после изменения — значение перечитывается. Неизвестный/HDMI/USB state не перезаписывается; остаётся оригинальный OEM пункт как fallback.
- Настройка не переключает текущий вход, не управляет HDMI HAL или оптическими модулями. Учитывается общий путь boot source, поэтому нельзя насильно перезаписывать нестандартные состояния.

## Софтверные проверки

- `OemPowerOnAppPolicyTest` проверяет whitelist, package name, отсутствие списка, OEM unknown state, подтверждение записи, ошибки и повторный выбор.
- `test-light-mode-android.yml` проверяет Java 8 Android 13 сборку и pure JVM тесты.
- `build-tvsettingsplus-inline-v29.yml` собирает и подписывает экспериментальную APK; тестирует политики, DEX, сертификаты и неизменённые ресурсы.
- Не отключает KuSettings. Блютуз-автосопряжение и резервный монитор охлаждения ещё требуют отдельного переноса/тестирования.

Основание: read-only JADX audit `PowerOnAppSecondaryController` в Run 43091564974 и исходный `PowerOnSourceSecondaryController`.
