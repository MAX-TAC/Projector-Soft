# TvSettingsPlus MOD v25 — перенос системных переходов KuSettings

**Ревизия: 8052/Android 13. 11 ноября 2026. Статус: экспериментальная сборка.**

## Что добавлено в native Android TV

1. `Об устройстве · Проектор` (ранее `Система · Проектор`) объединяет существующие сведения, диагностику и ручное чтение температуры (v24), плюс **«Обновление прошивки»**.
2. «Обновление прошивки» открывает **существующий заводской System page** `com.android.tv.settings.uicustom.MainActivity` через проверенное OEM действие `android.settings.DEVICE_INFO_SETTINGS` (factory page 7). Заводской экран содержит `tciv_system_local_update` и `tciv_system_online_update`. Никаких прямых вызовов `RuiYunOta` и автообновлений.
3. В `Источники · Проектор` добавлено **«Приложение при включении»**. Оно открывает оригинальный Source page (factory page 3) с `tciv_source_power_on_app` и заводским `PowerOnAppSecondaryController`. Переход доступен и на платах без подтверждённого HDMI (автозапуск приложения не зависит от физического HDMI).
4. Оба перехода скрываются при отсутствии соответствующего ID OEM ресурса или компонента Activity — не показываем фиктивные функции на других вариантах устройства.
5. Нативные AOSP Wi‑Fi, время, локаль и список приложений уже используются через старые KuSettings intent aliases; новые одноимённые пункты, дублирующие системное меню, не добавляем.
6. KuSettings, KuSourceRJ, SystemInfo, нажатия кнопок источника, изоляция CEC/game/resetTrapezoid, ToF и OTA-настройки **не изменяются**.

## Что это не переносит полностью

- Экран обновлений по-прежнему является отдельной OEM Activity, встроенной в исходный TvSettingsPlus. Это **совместимая навигация**, а не полное воспроизведение окон OTA в панели Android TV.
- Выбор приложения при включении остаётся оригинальным OEM подменю, не новой реализацией запуска приложений.
- Старый `KuSettings.MyAutoBluetoothActivity` не равен `AddAccessoryActivity`, поэтому автоматическое Bluetooth-подключение остаётся неподтверждённым.
- `KuSettings.MySetTimeService` каждую минуту восстанавливает `KuSourceRJ.TimeService`. До аппаратной проверки watchdog **KuSettings не отключать**.
- `settingApps` в системной конфигурации продолжает ссылаться на `com.my.settings`; APK-only изменения этого не исправляют.
- Отдельной адаптированной сборки и аппаратной проверки текущей прошивки 8054 всё ещё нет.

## Сборка и проверки

- Новый v25 workflow использует OEM 8052 APK, проверяет подписание, целостность DEX/ресурсов, intent aliases и версию.
- JVM-тест `OemDelegatedMenuPolicyTest` проверяет отсутствие «призрачных» пунктов и наличие разных заводских маршрутов для локального/онлайн обновления.
- Тесты не доказывают доступности OEM функций на реальном устройстве.

## Следующие шаги

1. Изучить оставшиеся Bluetooth auto reconnect/legacy intent dependencies.
2. Проверить поведение ключей/экранной заставки и функций при включении в заводских контроллерах перед переносом обработчиков.
3. Завершить runtime-проверку KuSourceRJ.TimeService и KuSettings activity/service entry points.
4. Только затем готовить отдельную совместимость и альфа-версию для установленной 8054.
