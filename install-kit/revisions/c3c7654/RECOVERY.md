# Возврат STOCK на 8054

Текущий статус — `ROLLBACK_NOT_VERIFIED`. Поставляемый STOCK имеет versionCode 1, MOD — 33. Оба APK имеют одинаковые пакет, сертификат и shared UID. Для обычной замены понижать versionCode нельзя. Закреплённый STOCK нужен как эталон для проверки фактических байтов после восстановления. [Правила Android versionCode](https://developer.android.com/studio/publish/versioning)

## A. Штатное удаление обновления через PackageManager

Android 13 AOSP предоставляет пакетный путь `uninstallSystemUpdates` для `FLAG_UPDATED_SYSTEM_APP`. PackageManager работает с записью обновления и сохранённой записью встроенного системного пакета. Перед удалением действуют проверки пользователя, разрешений и системных ограничений. Для понижения системного приложения AOSP требует администратора либо профиль администратора. При переходе к меньшему versionCode или иному appId флаг сохранения данных сбрасывается, поэтому v33 → v1 следует считать операцией с риском удаления данных Settings. Shared UID требует отдельной сверки appId, состояния и прав остальных участников. [PackageManagerShellCommand](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-13.0.0_r1/services/core/java/com/android/server/pm/PackageManagerShellCommand.java) · [DeletePackageHelper](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-13.0.0_r1/services/core/java/com/android/server/pm/DeletePackageHelper.java)

В AOSP пакетный маршрут запрашивает и передаёт установщику запись пользователя 0. Без указания пакета он перебирает системные обновления всех пакетов. Для 8054 нужно подтвердить встроенный APK по пути `/system_ext/priv-app/TvSettingsPlus/TvSettingsPlus.apk`, состояние владельца и фактический пакетный маршрут с доступом из обычной ADB shell. Вывод справки годится для оценки доступного интерфейса. Политика прошивки, действующие права, сохранность данных и результат возврата через этот интерфейс остаются неизвестными. [PackageInstallerService](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-13.0.0_r1/services/core/java/com/android/server/pm/PackageInstallerService.java)

После отдельно разрешённой проверки восстановления подтверждением служат активный встроенный путь, v1, точный STOCK SHA-256, соответствующие подпись и shared UID, отсутствие `UPDATED_SYSTEM_APP`, доступность Settings и критических OEM-служб, состояние исходных параметров и работоспособность ADB. Сохранение результата и доступности ADB после перезагрузки проверяется в отдельном согласованном сеансе.

## B. Удаление обновления через настройки

В стандартном Android 13 есть UI для управления обновлёнными системными приложениями. Доступ зависит от статуса пакета, администрирования и ограничений пользователя. В AOSP Settings сценарий понижения, связанный с кнопкой отключения, способен дополнительно отключить пакет. Для критического `com.android.tv.settings` подходит только отдельно подтверждённое действие по удалению обновления без отключения. Штатный TV Settings содержит ресурсы соответствующего действия. Наличие пункта и точное действие на 8054 предстоит проверить. Если UI вызывает тот же PackageManager, риск очистки данных при v33 → v1 сохраняется. Результат проверяется теми же признаками, что и в варианте A. [Android 13 Settings](https://raw.githubusercontent.com/aosp-mirror/platform_packages_apps_settings/android-13.0.0_r1/src/com/android/settings/applications/appinfo/AppButtonsPreferenceController.java) · [Ресурсы AOSP TvSettings](https://android.googlesource.com/platform/packages/apps/TvSettings/%2B/42153c3cb71dd076ce57aa78fce5413af25a309f/Settings/res/values/strings.xml)

## C. Заводской сброс

AOSP `RecoverySystem.rebootWipeUserData` передаёт recovery запрос на очистку пользовательских данных. Если этот путь очищает раздел с обновлением в `/data/app` и сохранён отдельный системный раздел, Android при следующей загрузке может выбрать встроенный APK. Для 8054 это условный вывод. OEM recovery, схема разделов, состояние OTA и возможное повторное развёртывание обновления не проверены. Ожидайте потерю приложений, аккаунтов, настроек, ADB-авторизации и возможную недоступность прежнего транспорта. Для подтверждения нужны признаки STOCK из варианта A и проверка OEM-функций после первичной настройки. Сброс исключён из первой процедуры возврата. [RecoverySystem Android 13](https://raw.githubusercontent.com/aosp-mirror/platform_frameworks_base/android-13.0.0_r1/core/java/android/os/RecoverySystem.java)

Диагностика STOCK фиксирует предпосылки для решения и значения inactivity. Команды изменения пакета, сброса и перезапуска отсутствуют в процедуре. До принятия результата диагностики действует `NOT_READY_FOR_DEVICE_INSTALL`.
